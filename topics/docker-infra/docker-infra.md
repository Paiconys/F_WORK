### Docker

#### Коротко
Контейнеризация: упаковать приложение и окружение, чтобы одинаково запускать везде.

#### Развёрнуто
Image — неизменяемый шаблон; container — запущенный процесс; volume — данные вне жизненного цикла контейнера. Зачем: меньше «у меня работает», изолированные зависимости, проще CI/CD. Не путать с ВМ: контейнеры делят ядро хоста.

---

### docker compose

#### Коротко
Описание и запуск нескольких сервисов одной конфигурацией (app, db, redis, …).

#### Развёрнуто
Сервисы, сети, volumes, env, depends_on/healthcheck. Compose — оркестрация на одну машину/dev/prod-простой стенд; не замена Kubernetes. На собесе: зачем несколько контейнеров вместо одного «всё сразу» — изоляция и масштабирование ролей.

### env-переменные / секреты

#### Коротко
Конфиг и секреты приходят из окружения, а не хардкодятся в репозиторий. 

#### Развёрнуто
`SECRET_KEY`, пароли БД, флаги DEBUG. Локально `.env` (в gitignore), в проде — секреты платформы. `.env.example` показывает ключи без значений.

### image vs container vs volume

#### Коротко
Image — неизменяемый шаблон; container — запущенный процесс из image; volume — постоянное хранилище вне жизненного цикла контейнера.

#### Развёрнуто
Пересборка контейнера не должна убивать данные БД и загруженные media — поэтому volumes. Image версионируют/пушат в registry.

### Reverse proxy (nginx)

#### Коротко
Входной HTTP-сервер перед приложением: TLS, статика, проксирование на backend.

#### Развёрнуто
Клиент бьёт в nginx; дальше `/api` → app, статика с диска, иногда `/ws` → ASGI. Зачем: один origin, сжатие, буферизация, безопасность, разгрузка app-сервера от статики. Альтернативы: Caddy, Traefik, cloud LB.

### логирование

#### Коротко
Системная запись событий и ошибок с уровнями, вместо `print` в проде. 

#### Развёрнуто
Модуль `logging`: DEBUG/INFO/WARNING/ERROR. Нужны для расследования инцидентов. Не логировать токены/пароли/персональные данные без нужды.
