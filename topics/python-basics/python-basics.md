## Python Types

### Какие бывают типы данных в Python

#### Коротко
Встроенные типы делят на числа, последовательности, множества, словари, bool/None, байты — и всё это объекты; плюс типы ваших классов. 

#### Развёрнуто
- **Числа:** `int`, `float`, `complex`
- **Текст:** `str` 
- **Последовательности:** `list`, `tuple`, `range` 
- **Множества:** `set`, `frozenset` 
- **Отображения:** `dict` 
- **Логика/пусто:** `bool`, `NoneType` 
- **Бинарные:** `bytes`, `bytearray`, `memoryview` 
Отдельно удобно смотреть через призму **изменяемости** (следующий вопрос), но «какие бывают» на собесе ждут именно эти группы + понимание, что пользовательский класс — тоже тип.

---

### Какие типы данных относятся к изменяемым, какие нет

#### Коротко
Изменяемые — `list`, `dict`, `set`, `bytearray`. Неизменяемые — `int`, `float`, `str`, `tuple`, `frozenset`, `bool`, `None`, `bytes`. 

#### Развёрнуто
Mutable меняются «на месте» (`append`, запись по ключу). Immutable при изменении дают новый объект (`s + "!"`). Отсюда следствия: ключи `dict`/`элементы set` должны быть hashable (обычно immutable); дефолт `def f(a=[])` опасен; передача list в функцию позволяет менять его снаружи, а «переназначение» `x = 1` внутри функции — нет.

#### Пример
Код: [`mutability_demo.py`](./examples/mutability_demo.py)

```python
"""Mutable vs immutable и передача в функцию.

Dependencies: none (stdlib)
"""


def rebind(x):
    x = [99]  # локальная перепривязка — снаружи не видно
    return x


def mutate(x):
    x.append(99)  # мутация объекта — видно снаружи


a = [1]
rebind(a)
print(a)  # [1]

mutate(a)
print(a)  # [1, 99]
```

### Чем отличаются операторы == и is

#### Коротко
`==` — равны по значению; `is` — это один и тот же объект в памяти. 

#### Развёрнуто
`==` опирается на `__eq__`. `is` сравнивает identity (`id`). Для `None` пишут `is None`. Не проверяй строки/числа через `is`: интернирование может дать ложное ощущение правила. В бизнес-логике почти всегда `==`.

#### Пример
Код: [`is_vs_eq.py`](./examples/is_vs_eq.py)

```python
"""

Dependencies: none (stdlib)
== сравнивает значение, is — идентичность объекта."""

a = [1, 2]
b = [1, 2]
c = a

print(a == b)  # True  — одинаковое содержимое
print(a is b)  # False — разные объекты
print(a is c)  # True  — тот же объект
```

### Что такое глубокая и поверхностная копия? Зачем нужны? Как их сделать?

#### Коротко
Поверхностная копирует верхний уровень (вложенное общее); глубокая — всё дерево объектов независимо. 

#### Развёрнуто
`copy.copy(obj)` / `list.copy()` / `dict.copy()` — shallow. `copy.deepcopy(obj)` — deep. Нужны, когда «правка копии не должна трогать оригинал». Ошибка новичка: скопировали list of dict и удивились, что dict внутри общий.

## Python Functions

### Как в Python передаются аргументы в функцию (изменяемые и неизменяемые)

#### Коротко
В функцию передаётся ссылка на объект; перепривязка имени локальна, мутация объекта видна снаружи. 

#### Развёрнуто
Это не «по значению» и не совсем «по ссылке как в C++». Вызов даёт тот же объект. `lst.append(1)` изменит исходный list. `lst = []` внутри функции только локально отвяжет имя. Поэтому контракт функции с mutable нужно документировать: «изменит переданный dict» или копировать вход.

#### Пример
Код: [`mutability_demo.py`](./examples/mutability_demo.py)

```python
"""Mutable vs immutable и передача в функцию.

Dependencies: none (stdlib)
"""


def rebind(x):
    x = [99]  # локальная перепривязка — снаружи не видно
    return x


def mutate(x):
    x.append(99)  # мутация объекта — видно снаружи


a = [1]
rebind(a)
print(a)  # [1]

mutate(a)
print(a)  # [1, 99]
```

### Что такое args и kwargs? Чем представлены?

#### Коротко
`*args` — кортеж лишних позиционных аргументов, `**kwargs` — словарь лишних именованных. 

#### Развёрнуто
Нужны для обёрток, декораторов, проброса в `super().__init__(*args, **kwargs)`. Имена условные, синтаксис `*`/`**` обязателен. При вызове `f(*args, **kwargs)` наоборот распаковывают.

#### Пример
Код: [`args_kwargs_demo.py`](./examples/args_kwargs_demo.py)

```python
"""

Dependencies: none (stdlib)
*args — кортеж, **kwargs — словарь."""


def f(a, *args, **kwargs):
    print("a=", a)
    print("args=", args)
    print("kwargs=", kwargs)


f(1, 2, 3, x=10, y=20)
```

### что такое lambda функция. кейсы применения

#### Коротко
Однострочная анонимная функция из одного выражения — для коротких callback’ов. 

#### Развёрнуто
`lambda x: x[1]` как `key` в `sorted`, редко в `map`/`filter`. Если нужны условия, несколько строк, имя для трейсбека — обычный `def`. Lambda не место для бизнес-логики.

#### Пример
Код: [`lambda_demo.py`](./examples/lambda_demo.py)

```python
"""

Dependencies: none (stdlib)
lambda — короткое выражение, не полноценная функция."""

nums = [3, 1, 2]
print(sorted(nums, key=lambda x: x))
print(list(map(lambda x: x * 2, nums)))
```

---

### Что такое аннотации типов, зачем они нужны, когда выполняются

#### Коротко
Подсказки типов для людей/**IDE** — Integrated Development Environment (среда разработки)/mypy; Python сам по ним обычно не проверяет и не падает в runtime. 

#### Развёрнуто
Пишутся как `def f(x: int) -> str`. Живут в `__annotations__`. Выполняются/сохраняются при определении функции (или откладываются как строки с `from __future__ import annotations`). Валидацию входных данных в вебе всё равно делают serializers/модели, а не аннотации.

---

### Что такое тернарный оператор, как записывается

#### Коротко
Выражение вида `A if условие else B`. 

#### Развёрнуто
Это выражение, его можно присвоить/вернуть. Не замена блоку `if` с несколькими действиями. Вложенные тернарники на ревью обычно режут.

## Python Iterators

### list comprehension / generator expression — отличия

#### Коротко
Comprehension сразу строит list в памяти; genexp лениво отдаёт элементы. 

#### Развёрнуто
`[x for x in xs if ...]` vs `(x for x in xs if ...)`. Для больших потоков genexp/генератор безопаснее по RAM. Для маленьких коллекций list comp читаемее и нормален.

---

### Что такое генератор? Как написать на Python генератор?

#### Коротко
Ленивый итератор, который пишут функцией с `yield` или generator expression. 

#### Развёрнуто
`def gen(): yield 1; yield 2` — при вызове сразу не считается. Память экономится на больших потоках. `(x*x for x in xs)` — genexp. Генератор — частный случай итератора.

#### Пример
Код: [`iter_gen_demo.py`](./examples/iter_gen_demo.py)

```python
"""

Dependencies: none (stdlib)
Итератор vs генератор."""


def gen():
    yield 1
    yield 2


g = gen()
print(next(g), next(g))

# generator expression — лениво
squares = (x * x for x in range(5))
print(list(squares))
```

---

### Что такое итератор? Что такое итерируемый объект?

#### Коротко
Итерируемый — то, что можно обойти в `for`; итератор — объект, который помнит позицию и отдаёт следующий элемент через `__next__`. 

#### Развёрнуто
Iterable даёт iterator через `iter()`. Iterator реализует `__next__` и обычно сам `__iter__`. Список можно обходить много раз (каждый раз новый iterator); сам iterator — одноразовый. `for` скрывает этот протокол.

#### Пример
Код: [`iter_gen_demo.py`](./examples/iter_gen_demo.py)

```python
"""

Dependencies: none (stdlib)
Итератор vs генератор."""


def gen():
    yield 1
    yield 2


g = gen()
print(next(g), next(g))

# generator expression — лениво
squares = (x * x for x in range(5))
print(list(squares))
```

## Python Stdlib

### `__str__` / `__repr__` — зачем

#### Коротко
`str` — для людей; `repr` — однозначное отладочное представление. 

#### Развёрнуто
`print(obj)`/`admin` часто используют `__str__`. `repr` помогает в логах и REPL. Хороший `__str__` у модели экономит время в shell/admin.

---

### dataclass — что это, зачем

#### Коротко
Декоратор, который сам собирает шаблонный код для класса-данных (`__init__`, сравнение и т.д.). 

#### Развёрнуто
Удобно для DTO/конфигов без тяжёлой логики. Не замена моделям ORM. Есть `frozen`, `slots` и т.п.

#### Пример
Код: [`dataclass_demo.py`](./examples/dataclass_demo.py)

```python
"""

Dependencies: none (stdlib)
dataclass — меньше шаблонного кода для данных."""

from dataclasses import dataclass


@dataclass
class User:
    name: str
    age: int = 0


print(User("Ada", 36))
```

### Exceptions: как обрабатывать, зачем свои исключения

#### Коротко
Ошибки сигнализируют через исключения; свои типы нужны, чтобы ловить доменные случаи отдельно от прочих сбоев. 

#### Развёрнуто
`try/except/else/finally`. Ловите конкретные типы, не всё подряд. На границе API превращаете в понятный HTTP-ответ. Свои классы (`ValidationDomainError`) делают обработку выразительной.

---

### Что такое context manager (`with`)? Зачем нужен?

#### Коротко
Протокол гарантированного входа/выхода (`__enter__`/`__exit__`), чтобы ресурсы закрывались даже при ошибке. 

#### Развёрнуто
`with open(path) as f` закроет файл. `with transaction.atomic()` откатит транзакцию при исключении. Можно писать свои через класс или `@contextmanager`.

#### Пример
Код: [`context_manager_demo.py`](./examples/context_manager_demo.py)

```python
"""

Dependencies: none (stdlib)
context manager — гарантия очистки ресурса."""


class CM:
    def __enter__(self):
        print("open")
        return self

    def __exit__(self, exc_type, exc, tb):
        print("close")
        return False  # не глотаем исключения


with CM():
    print("work")
```

## Python Packaging

### `if __name__ == "__main__"`

#### Коротко
Код под этим условием выполняется только при прямом запуске файла, не при импорте. 

#### Развёрнуто
Позволяет держать утилиты импортируемыми и одновременно иметь CLI-вход. Паттерн скриптов и `__main__.py`.

---

### Poetry

#### Коротко
Современный менеджер зависимостей вокруг `pyproject.toml` + lock-файла. 

#### Развёрнуто
Решает версии жёстче, чем «голый» requirements без pin-стратегии, умеет группы dev-deps и сборку пакета. Poetry — современная альтернатива pip+requirements с lock-файлом.

---

### Абсолютные vs относительные импорты

#### Коротко
Абсолютный — путь от корня пакета. Относительный — относительно текущего модуля (`.` / `..`).

#### Развёрнуто
`from myapp.models import X` vs `from .models import X`. Абсолютные проще читать в большом проекте; относительные удобны внутри пакета. Скрипт, запущенный «как файл», часто ломает относительные импорты — нужна пакетная структура/`-m`.

---

### Модуль и пакет

#### Коротко
Модуль — файл `.py`. Пакет — набор модулей в директории (пространство имён).

#### Развёрнуто
Импорты строят структуру проекта (`package.module`). Пакет обычно с `__init__.py` (namespace packages — отдельная тема). Без пакетов проект быстро превращается в кашу файлов. На собесе: чем модуль отличается от пакета и зачем `__init__.py`.

---

### Что такое виртуальное окружение? Зачем оно нужно? Какие инструменты для этого используются?

#### Коротко
Изолированный набор пакетов проекта, чтобы зависимости разных проектов не конфликтовали. 

#### Развёрнуто
Инструменты: `venv` (стандарт), `virtualenv`, Poetry, Pipenv, conda. Типичный поток: создать → активировать → `pip install -r requirements.txt`. В git не кладут. Docker образ — другая изоляция; локальный venv всё равно удобен для IDE.

## Python Complexity

### Как оценивается сложность алгоритмов и почему? Что такое Big O notation?

#### Коротко
Big O описывает, как растут время/память при росте размера входа — чтобы сравнивать алгоритмы независимо от машины. 

#### Развёрнуто
Смотрят порядок: O(1), O(log n), O(n), O(n log n), O(n²)… На практике важны и константы, и реальные данные, но Big O ловит принципиально плохие подходы (полный перебор вместо индекса). «Почему» — предсказуемость масштабирования.

---

### Какая сложность основных операций в коллекциях?

#### Коротко
Индекс в `list` — O(1), поиск в list — O(n); средний `get`/`in` в `dict`/`set` — O(1). 

#### Развёрнуто
`append` у list — амортизированно O(1); `insert(0)`/`pop(0)` — O(n). `dict`/`set` — хеш-таблицы (средний O(1), теоретический худший хуже). Отсюда выбор структуры: частый `in` по большому набору → set, не list.
