# English (grammar for interviews)

B1–B2 tables: **form + when + short prompts**.  
Subjects grouped where the verb form is the same.

**Groups**
| Group | Subjects |
| --- | --- |
| I | I |
| you / we / they | you, we, they |
| he / she / it | he, she, it |

Legend: **+** affirmative · **−** negative · **?** question

---

## Present Simple

**When:** facts, habits, schedules, permanent situations.  
**Signals:** always, usually, every day, often, never.

| | I | you / we / they | he / she / it |
| --- | --- | --- | --- |
| **+** | I work | you/we/they work | he/she/it **works** |
| **−** | I **do not** / **don't** work | you/we/they **don't** work | he/she/it **does not** / **doesn't** work |
| **?** | **Do** I work? | **Do** you/we/they work? | **Does** he/she/it work? |
| Short yes/no | Yes, I do. / No, I don't. | Yes, we do. / No, they don't. | Yes, she does. / No, it doesn't. |

**Be (Present Simple)**

| | I | you / we / they | he / she / it |
| --- | --- | --- | --- |
| **+** | I **am** / I'm | you/we/they **are** / you're | he/she/it **is** / he's |
| **−** | I'm **not** | you/we/they **aren't** | he/she/it **isn't** |
| **?** | **Am** I…? | **Are** you/we/they…? | **Is** he/she/it…? |

**Examples**
- + I work with Django. / She works with Django.
- − We don't use Flask. / He doesn't use Flask.
- ? Do you write tests? / Does it cache results?

**Why:** describe your stack and habits (*I usually deploy on Fridays*).

**Prompts**
1. What do you usually do at work?
2. Does your team use Docker?

## Present Continuous

**Form:** `am / is / are + V-ing`  
**When:** now, temporary process, current project.  
**Signals:** now, at the moment, currently, today.

| | I | you / we / they | he / she / it |
| --- | --- | --- | --- |
| **+** | I **am** working | you/we/they **are** working | he/she/it **is** working |
| **−** | I'm **not** working | you/we/they **aren't** working | he/she/it **isn't** working |
| **?** | **Am** I working? | **Are** you/we/they working? | **Is** he/she/it working? |

**Examples**
- + I'm working on auth. / They're refactoring the API.
- − She isn't deploying today.
- ? Are you working on that ticket?

**Why:** talk about the current task in an interview.

**Prompt:** What are you working on right now?

## Past Simple

**Form:** regular `V-ed` / irregular `V2`  
**When:** finished action at a known past time.  
**Signals:** yesterday, last week, in 2024, ago.

| | I / you / we / they / he / she / it |
| --- | --- |
| **+** | I/you/we/they/he/she/it **worked** / **deployed** / **went** |
| **−** | I/you/… **did not** / **didn't** work (base form after *didn't*) |
| **?** | **Did** I/you/… work? |

**Be (Past Simple)**

| | I / he / she / it | you / we / they |
| --- | --- | --- |
| **+** | I/he/she/it **was** | you/we/they **were** |
| **−** | wasn't | weren't |
| **?** | **Was** I/he/she/it…? | **Were** you/we/they…? |

**Examples**
- + We deployed to prod yesterday. / She fixed the bug.
- − I didn't break the build.
- ? Did you write the migration?

**Why:** tell concrete project stories with a clear time.

**Prompt:** Tell me about a bug you fixed last month.

---

## Past Continuous

**Form:** `was / were + V-ing`  
**When:** background action / process at a past moment.  
**Signals:** while, when, at 5 pm yesterday.

| | I / he / she / it | you / we / they |
| --- | --- | --- |
| **+** | I/he/she/it **was** debugging | you/we/they **were** debugging |
| **−** | wasn't debugging | weren't debugging |
| **?** | **Was** I/he/she/it debugging? | **Were** you/we/they debugging? |

**Examples**
- + I was debugging when the alert fired.
- − They weren't testing that path.
- ? Were you monitoring the service?

**Why:** incident stories (*what was happening when X happened*).

**Prompt:** What were you doing when the service went down?

---

## Present Perfect

**Form:** `have / has + V3` (past participle)  
**When:** experience, result now, unfinished time (today, this year).  
**Signals:** ever, never, already, yet, so far, just.

| | I / you / we / they | he / she / it |
| --- | --- | --- |
| **+** | I/you/we/they **have** used Redis | he/she/it **has** used Redis |
| **−** | haven't used | hasn't used |
| **?** | **Have** I/you/we/they used…? | **Has** he/she/it used…? |
| Short | Yes, I have. / No, we haven't. | Yes, she has. / No, it hasn't. |

**Examples**
- + I've used Redis. / She has worked with Celery.
- − We haven't shipped that yet.
- ? Have you ever written a migration?

**vs Past Simple:** Perfect = experience/result (*I've used Docker*). Simple = when (*I used Docker in 2025*).

**Why:** answer “Have you worked with X?” without inventing a date.

**Prompts**
1. Have you ever worked with Docker?
2. Has your team already migrated to Postgres?

## Present Perfect Continuous

**Form:** `have / has been + V-ing`  
**When:** action started in the past and is still going / focus on duration.

| | I / you / we / they | he / she / it |
| --- | --- | --- |
| **+** | I/you/we/they **have been** learning | he/she/it **has been** learning |
| **−** | haven't been learning | hasn't been learning |
| **?** | **Have** … been learning? | **Has** … been learning? |

**Example:** I've been preparing for interviews for two months.

**Why:** show ongoing learning or long work on a feature.

**Prompt:** How long have you been learning asyncio?

## Past Perfect

**Form:** `had + V3` (same for all subjects)  
**When:** earlier past before another past action.

| | all subjects |
| --- | --- |
| **+** | I/you/he/… **had** failed / **had** tested |
| **−** | hadn't failed |
| **?** | **Had** I/you/he/… failed? |

**Example:** The job had failed before we noticed.

**Why:** order events in a postmortem.

**Prompt:** Explain an incident with *before* / *after* using Past Perfect.

---

## Future: will

**Form:** `will + V` (same for all)  
**When:** decision now, promise, prediction.

| | all subjects |
| --- | --- |
| **+** | I/you/he/… **will** check |
| **−** | **won't** check |
| **?** | **Will** I/you/he/… check? |

**Example:** I'll check the logs. / Will it scale?

---

## Future: going to

**Form:** `am/is/are + going to + V`  
**When:** plan / intention based on evidence.

| | I | you / we / they | he / she / it |
| --- | --- | --- | --- |
| **+** | I'm going to refactor | you're/we're/they're going to refactor | he's/she's/it's going to refactor |
| **−** | I'm not going to… | aren't going to… | isn't going to… |
| **?** | Am I going to…? | Are you/we/they going to…? | Is he/she/it going to…? |

**Example:** We're going to add an index.

## Future arrangement: Present Continuous

**When:** fixed plan in the calendar.

| **+** | I'm meeting the team at 3. |
| **?** | Are you joining the call tomorrow? |

## Active / Passive Voice

**Active:** Subject does the action.  
**Passive:** Focus on the object / process (`be + V3`).

| | Active | Passive |
| --- | --- | --- |
| Idea | We deployed the service. | The service **was deployed**. |
| Idea | Redis stores the cache. | The cache **is stored** in Redis. |
| Idea | Celery sends the email. | The email **is sent** by Celery. |

### Passive by tense (all subjects use the same pattern; only *be* changes)

| Tense | Passive form | Example |
| --- | --- | --- |
| Present Simple | am/is/are + V3 | The token **is verified**. |
| Present Continuous | am/is/are being + V3 | The job **is being processed**. |
| Past Simple | was/were + V3 | The bug **was fixed**. |
| Present Perfect | have/has been + V3 | The issue **has been fixed**. |
| Modal | can/must/should be + V3 | Requests **must be authenticated**. |
| will | will be + V3 | The release **will be deployed**. |

### Passive: + / − / ? (Present Simple)

| | I | you / we / they | he / she / it |
| --- | --- | --- | --- |
| **+** | I am notified | you/we/they are notified | he/she/it is notified |
| **−** | I'm not notified | aren't notified | isn't notified |
| **?** | Am I notified? | Are you notified? | Is it notified? |

### Passive: + / − / ? (Past Simple)

| | I / he / she / it | you / we / they |
| --- | --- | --- |
| **+** | was deleted | were deleted |
| **−** | wasn't deleted | weren't deleted |
| **?** | Was it deleted? | Were they deleted? |

**When Passive is useful:** process > author; unknown author; docs / postmortems.  
**When Active is better:** your contribution (*I implemented…*).

**Prompts**
1. Rewrite actively: “The token is verified by the middleware.”
2. Rewrite passively: “Celery sends the email.”
3. Make a question: “The migration was applied.” → Was the migration applied?

## Conditionals (0–3)

| Type | Form | When | Example |
| --- | --- | --- | --- |
| 0 | If + Present, Present | always true | If Redis is down, the cache misses. |
| 1 | If + Present, will + V | real future | If the test fails, we will block the merge. |
| 2 | If + Past, would + V | unreal now | If I had more time, I would add metrics. |
| 3 | If + Past Perfect, would have + V3 | regret about past | If we had tested it, we would have caught the bug. |

**Questions:** *What will you do if…?* / *What would you do if…?*

**Prompt:** If the database is slow, what will you check first?

---

## Modals

Same form for all subjects: `modal + V` (no -s).

| Modal | Use | + | − | ? |
| --- | --- | --- | --- | --- |
| can | ability / possibility | I can explain N+1. | I can't… | Can you…? |
| must | strong rule / necessity | You must validate server-side. | You mustn't… (prohibition) | Must we…? |
| have to | obligation | We have to rotate keys. | don't/doesn't have to | Do I have to…? |
| should | advice | We should add an index. | shouldn't | Should we…? |
| might / may | probability | It might be a race. | might not | Might it…? |
| would | hypothesis / polite | I would start with logs. | wouldn't | Would you…? |

**Prompt:** What should we do before a production migration?

## Articles (a / an / the) — short

| | When | Example |
| --- | --- | --- |
| a / an | one of many, first mention | a bug, an API |
| the | specific / already known / unique | the bug we found, the database |
| zero | languages, most tech names in general talk | Python, Docker, production |

**Prompt:** Fix: “I fixed bug in the Redis.”

## Countable / Uncountable (IT)

| Countable | Uncountable |
| --- | --- |
| a bug, two services | information, advice, traffic |
| many / few | much / little |
| How many requests? | How much latency? |

**Prompt:** much or many — “___ requests per second”?

## Comparatives — short

| | Form | Example |
| --- | --- | --- |
| short adj | -er / the -est | faster, the fastest |
| long adj | more / the most | more reliable |
| equal | as … as | as fast as Redis |
| irregular | better, worse | better latency |

**Prompt:** Postgres is ___ than SQLite for concurrency.

## Useful interview chunks

| Goal | Phrase |
| --- | --- |
| Start | So, basically… / In short… |
| Clarify | Do you mean X or Y? |
| Unsure | I'm not sure, but I'd check… |
| Experience | I've worked with… / In my last project… |
| Trade-off | The trade-off is… |
| Incident | First we… then we… finally we… |
| Repeat | Could you repeat the last part? |

**Speaking prompts (30–60 sec aloud)**
1. Explain what a REST API is. (+ Present Simple)
2. Explain N+1 and how to fix it.
3. Describe a production bug (Past Simple + Past Perfect).
4. Say what you are working on (Present Continuous).
5. Give advice about secrets in git (*should* / *must*).
6. Ask three interview questions using *Do/Does/Did/Have/Has*.
