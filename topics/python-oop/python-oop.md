### OOP — как применяли в моделях/сериализаторах

#### Коротко
Домен и границы **API** — Application Programming Interface (программный интерфейс приложения) разложены по классам с ясной ответственностью. 

#### Развёрнуто
Model хранит данные/инварианты поля; Serializer — вход/выход API; Consumer — WS-поведение; validators/html_utils — чистые функции/хелперы рядом. Это и есть практический OOP, не ради UML.

### В Python нет модификаторов доступа… public, private и protected

#### Коротко
Всё доступно снаружи; `_name` — «не трогай» по договорённости, `__name` — name mangling, не настоящий private. 

#### Развёрнуто
Public — обычные имена. Protected — один underscore (конвенция команды/линтеров). Private — два underscore → `_Class__name`, чтобы меньше случайных коллизий в наследниках. Безопасности от злонамеренного доступа это не даёт.

### Зачем нужен метод super в классе?

#### Коротко
Чтобы вызвать следующий метод по **MRO** — Method Resolution Order (порядок разрешения методов) (обычно родителя) без жёсткого имени базового класса. 

#### Развёрнуто
Критичен при множественном наследовании/миксинах: `super().__init__(...)` идёт правильно по цепочке. В Py3 пишут `super()`. Хардкод `Parent.method(self)` ломается при ромбах и рефакторинге.

#### Пример
Код: [`super_demo.py`](./examples/super_demo.py)

```python
"""

Dependencies: none (stdlib)
super() идёт по MRO, не «всегда к прямому родителю по имени»."""


class A:
    def f(self):
        return "A"


class B(A):
    def f(self):
        return "B+" + super().f()


print(B().f())  # B+A
```

### Как в python реализуются методы объекта, класса и статические методы? Чем они отличаются?

#### Коротко
Обычный метод получает экземпляр (`self`); `@classmethod` — класс (`cls`); `@staticmethod` — ничего из объекта/класса автоматически. 

#### Развёрнуто
- **instance** — работа с данными объекта
- **classmethod** — фабрики/`from_json`, доступ к атрибутам класса 
- **staticmethod** — утилита в пространстве имён класса 
Отличие classmethod vs static: classmethod знает класс (важно при наследовании), static — просто функция.

#### Пример
Код: [`methods_demo.py`](./examples/methods_demo.py)

```python
"""

Dependencies: none (stdlib)
instance / class / static methods."""


class A:
    def inst(self):
        return "instance", self

    @classmethod
    def cls(cls):
        return "class", cls

    @staticmethod
    def st():
        return "static"


print(A().inst()[0], A.cls()[0], A.st())
```

### Какие базовые принципы ООП?

#### Коротко
Инкапсуляция, наследование, полиморфизм (часто добавляют абстракцию). 

#### Развёрнуто
Инкапсуляция — спрятать детали за API. Наследование — специализировать поведение. Полиморфизм — один интерфейс, разные реализации. Абстракция — моделировать только нужное. SOLID уже про качество дизайна классов, не «базовые 3 кита».

### Чем отличается атрибут класса от атрибута объекта?

#### Коротко
Атрибут класса общий для всех экземпляров; атрибут объекта принадлежит одному `self`. 

#### Развёрнуто
Объявление в теле класса (`x = []`) — class attr. Присвоение через `self.x = ...` — instance attr и может затенить class attr. Опасность: mutable class attr делится между всеми инстансами.

### Что такое diamond problem? Что такое MRO? Чем отличается MRO2 от MRO3? Зачем оно нужно?

#### Коротко
Ромб — два пути к одному предку; MRO — линейный порядок поиска методов; в Python 3 используют C3 (часто называют new-style/MRO «3»). 

#### Развёрнуто
Без чёткого порядка непонятно, чей метод вызвать и куда пойдёт `super()`. Python строит `__mro__` алгоритмом C3; если линеаризовать нельзя — ошибка при создании класса. «MRO2 vs MRO3» на собесе обычно про старый classic-classes vs новый C3 в Py3: на практике смотри `__mro__` и доверяй `super()`. Зачем нужно — предсказуемое множественное наследование.

#### Пример
Код: [`mro_demo.py`](./examples/mro_demo.py)

```python
"""

Dependencies: none (stdlib)
MRO / diamond — учебный пример к теории."""


class A:
    def f(self):
        return "A"


class B(A):
    def f(self):
        return "B+" + super().f()


class C(A):
    def f(self):
        return "C+" + super().f()


class D(B, C):
    pass


print(D().f())      # B+C+A  (C3)
print(D.__mro__)
```

### Что такое self в классах?

#### Коротко
Явная ссылка на конкретный экземпляр, с которым вызван метод. 

#### Развёрнуто
При `obj.method(x)` Python вызывает `Class.method(obj, x)`. Имя `self` — соглашение. Через него читают/меняют состояние объекта. Без понимания `self` путают классовые и объектные атрибуты.

#### Пример
Код: [`methods_demo.py`](./examples/methods_demo.py)

```python
"""

Dependencies: none (stdlib)
instance / class / static methods."""


class A:
    def inst(self):
        return "instance", self

    @classmethod
    def cls(cls):
        return "class", cls

    @staticmethod
    def st():
        return "static"


print(A().inst()[0], A.cls()[0], A.st())
```

### Что такое абстрактный класс? … в Python

#### Коротко
Класс-контракт с методами без реализации; экземпляр «как есть» не создают. Делают через `abc.**ABC** — Abstract Base Class (абстрактный базовый класс)` + `@abstractmethod`. 

#### Развёрнуто
Нужен, когда несколько реализаций обязаны иметь один интерфейс. Пока abstract-метод не реализован в наследнике — инстанцирование падает. Это дисциплина дизайна, не синтаксический сахар ради красоты.

### Что такое декораторы? … простой и с аргументом

#### Коротко
Функция (или класс), которая оборачивает другую функцию/класс, меняя поведение без правки её тела; синтаксис `@deco`. 

#### Развёрнуто
Простой декоратор принимает `fn` и возвращает `wrapper`. Декоратор с аргументами — фабрика: сначала вызывается с параметрами, возвращает настоящий декоратор. Кейсы: логирование, тайминг, `@login_required`, `@classmethod`. `functools.wraps` сохраняет метаданные.

#### Пример
Код: [`decorators_demo.py`](./examples/decorators_demo.py)

```python
"""

Dependencies: none (stdlib)
Простой декоратор и декоратор с аргументами."""

from functools import wraps


def simple(fn):
    @wraps(fn)
    def wrapper(*args, **kwargs):
        print("before")
        result = fn(*args, **kwargs)
        print("after")
        return result

    return wrapper


def repeat(n):
    def deco(fn):
        @wraps(fn)
        def wrapper(*args, **kwargs):
            for _ in range(n):
                fn(*args, **kwargs)

        return wrapper

    return deco


@simple
def hello():
    print("hi")


@repeat(2)
def ping():
    print("pong")


if __name__ == "__main__":
    hello()
    ping()
```

### Что такое метаклассы? …

#### Коротко
Класс, который создаёт классы (`type`); на Junior достаточно понимать идею, писать самим почти не нужно. 

#### Развёрнуто
Обычные классы создаёт `type`. Свой `metaclass` вмешивается в создание класса (`__new__`/`__init__` метакласса). ORM Django использует похожую магию для моделей. На собесе честный уровень: «знаю зачем, в проде сам не изобретаю».

---

### Что такое миксины?

#### Коротко
Небольшие классы-примеси с готовым поведением для подмешивания через множественное наследование. 

#### Развёрнуто
Сами по себе обычно не живут. Пример мышления: «добавить логирование/права» без раздувания базового класса. В Django CBV — `LoginRequiredMixin` и т.п. Требуют понимания MRO.

---

### Что такое ООП?

#### Коротко
Подход, где программа строится из объектов: данные + поведение + взаимодействие. 

#### Развёрнуто
Класс — чертёж, объект — экземпляр. В Python ООП соседствует с процедурным стилем; не всё обязано быть классом. В вебе объекты часто = сущности домена (`Comment`) и сервисы/компоненты фреймворка.
